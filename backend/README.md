## 🌟 ۱. معرفی و معماری سیستم (Overview & Architecture)

این بک‌اند بر پایه **معماری ماژولار ویژگی‌محور (Feature-First Modular Architecture)** و اصول **مهندسی امنیت سیستم (AppSec Hardening)** با استفاده از **Express.js** و **TypeScript** پیاده‌سازی شده است. سیستم به صورت کاملاً مستقل و ایزوله در پوشه `backend/` قرار گرفته و آماده اتصال به فرانت‌اند Next.js و استقرار در محیط‌های ابری یا سرورهای لینوکس/ویندوز است.

### 🛡️ ویژگی‌های امنیتی و فنی پیاده‌سازی شده:
1. **امنیت چندلایه‌ای (AppSec Hardening)**:
   - پیکربندی جامع `Helmet` برای مقابله با حملات XSS، Clickjacking و تزریق هدرها.
   - مهار حملات منع سرویس (DoS) و Brute-force با دو سطح Rate Limiting (`apiRateLimiter` عمومی و `strictRateLimiter` اختصاصی برای لاگین و فرم‌های رزرو).
   - اعتبارسنجی و پالایش سخت‌گیرانه کلیه ورودی‌ها (Body, Query, Params) با استفاده از `Zod`.
   - رمزنگاری کلمات عبور با الگوریتم `bcryptjs` (دور ۱۲ Salt Rounds).
   - سیستم احراز هویت بدون حالت (Stateless JWT) به همراه پشتیبانی هم‌زمان از کوکی‌های ایمن `HttpOnly; Secure; SameSite` و هدر `Authorization: Bearer`.
   - کنترل دسترسی بر مبنای نقش (RBAC) با نقش‌های مجزا: `ADMIN` (دکتر/مدیر ارشد)، `SECRETARY` (منشی و پذیرش) و `STAFF`.
   - مدیریت امن خطاها (Safe Error Masking) جهت جلوگیری از نشت Stack Trace و مسیرهای سرور در محیط Production.
2. **پایگاه داده و لایه دسترسی (Data Layer)**:
   - استفاده از **Prisma ORM** برای تضمین Type Safety سرتاسری و کارایی بالا.
   - پیش‌فرض دیتابیس لوکال SQLite (فایل `dev.db` بدون نیاز به نصب هیچ دیتابیس سرور خارجی).
   - امکان سوئیچ آنی به **PostgreSQL** یا **MySQL** در محیط عملیاتی صرفاً با تغییر متغیر `DATABASE_URL` در فایل `.env`.
3. **پوشش داده‌های واقعی کلینیک (Seeding)**:
   - اسکریپت Seed خودکار با داده‌های واقعی شامل ۶ مقاله بالینی، ۵ پروتکل درمانی، نظرات بیماران، پرسش‌های متداول، اطلاعات و ساعات کاری کلینیک.

## 🚀 ۳. نحوه راه‌اندازی و اجرا (Getting Started)

### پیش‌نیازها:
- Node.js نسخه 18 یا بالاتر
- مدیر بسته `npm`

### مراحل اجرا:

```powershell
# ۱. رفتن به پوشه بک‌اند
cd backend

# ۲. نصب وابستگی‌ها
npm install

# ۳. آماده‌سازی دیتابیس و جدول‌ها
npm run db:push

# ۴. کاشت داده‌های پیش‌فرض و کاربر ادمین
npm run db:seed

# ۵. اجرای پروژه در حالت توسعه (Dev با Hot Reload)
npm run dev
```

سرور روی آدرس زیر بالا خواهد آمد:
- **API Base URL**: `http://localhost:5000/api/v1`
- **Health Check**: `http://localhost:5000/health`

### اجرای تست‌های خودکار:
```powershell
npx tsx src/test-api.ts
```

### ساخت نسخه عملیاتی (Production Build):
```powershell
npm run build
npm start
```

### ۲. نوبت‌دهی و مشاوره مراجعین (Appointments - `/api/v1/appointments`)
| متد | مسیر | دسترسی | توضیحات |
| :--- | :--- | :--- | :--- |
| `POST` | `/` | عمومی (Rate Limited) | **ثبت درخواست ویزیت/مشاوره توسط بیمار** (نام، شماره، زمینه مراجعه، شیفت، پیام) |
| `GET` | `/` | منشی و مدیر | **لیست نوبت‌ها** با صفحه‌بندی (`page`, `limit`)، فیلتر وضعیت (`status`) و جستجو |
| `GET` | `/stats` | منشی و مدیر | آمار تجمیعی نوبت‌ها (نوبت‌های امروز، در انتظار، تایید شده و...) |
| `GET` | `/:id` | منشی و مدیر | مشاهده جزئیات یک نوبت خاص |
| `PATCH` | `/:id` | منشی و مدیر | **تغییر وضعیت نوبت** (`PENDING`, `CONTACTED`, `CONFIRMED`, `COMPLETED`, `CANCELLED`) به همراه یادداشت داخلی |
| `DELETE` | `/:id` | مدیر (ADMIN) | حذف پرونده نوبت |

## 🔗 ۶. راهنمای اتصال فرانت‌اند Next.js به بک‌اند (Frontend Connection)

برای برقراری ارتباط روان بین کلاینت Next.js و این بک‌اند:

1. در فایل ریشه `.env.local` پروژه Next.js متغیر زیر را قرار دهید:
   ```env
   NEXT_PUBLIC_API_URL=http://localhost:5000/api/v1
   ```
2. ارسال درخواست‌ها با استاندارد `fetch` یا کتابخانه‌هایی مانند `axios`:
   ```typescript
   export async function submitAppointment(data: AppointmentData) {
     const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL}/appointments`, {
       method: 'POST',
       headers: { 'Content-Type': 'application/json' },
       body: JSON.stringify(data),
     });
     return res.json();
   }
   ```
3. فرمت یکپارچه پاسخ‌های بازگشتی سرور:
   ```json
   {
     "success": true,
     "message": "عملیات با موفقیت انجام شد",
     "data": { ... },
     "meta": { "page": 1, "limit": 10, "total": 1, "totalPages": 1 },
     "timestamp": "2026-09-24T13:00:00.000Z"
   }
   ```
